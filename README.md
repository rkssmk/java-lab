# Java Lab v4.0 — подготовка к облачному запуску

Java Lab v4.0 добавляет к статической учебной платформе backend для аккаунтов и личного облачного прогресса. Это **подготовленная к развёртыванию техническая сборка**, а не действующий многопользовательский сервис: на GitVerse Pages backend не запускается, а публичная регистрация в конфигурации по умолчанию выключена.

## Что есть в проекте

- Прежняя учебная платформа Java Lab с картой 7 блоков / 72 уроков.
- Spring Boot API: регистрация, вход, выход, восстановление по одноразовому ключу, смена пароля, удаление аккаунта и синхронизация личного прогресса.
- PostgreSQL: таблицы пользователей, версий/подтверждений согласия и индивидуального прогресса (`JSONB`). Начальная роль PostgreSQL отделена от непривилегированной роли приложения; порт БД не опубликован.
- Разграничение прогресса по идентификатору аутентифицированного пользователя; оптимистический контроль версии при синхронизации нескольких устройств.
- Сессионная cookie `HttpOnly`, `Secure` в production, `SameSite=Lax`; CSRF-токен; PBKDF2-хеширование пароля; ограничение частоты попыток. Для JSON используется Jackson 3 и встроенный Hibernate mapper.
- Caddy reverse proxy: сайт и `/api` находятся на одном домене; PostgreSQL не опубликован в интернет.
- Резервное копирование базы в зашифрованный файл с отдельной HMAC-проверкой целостности; внешний исполнитель Java-кода выключен.

## Важное: регистрация выключена

В `.env.example` установлено:

```dotenv
APP_REGISTRATION_ENABLED=false
APP_LEGAL_LAUNCH_APPROVED=false
RUNNER_ENABLED=false
```

Не меняй эти флаги, пока не определён оператор, не подтверждено фактическое местонахождение всех БД/реплик/backup/logs, не согласованы документы, не проверены уведомления и трансграничный доступ с профильным юристом. Сервер дополнительно проверяет заполненность юридических реквизитов, отсутствие шаблонных полей в документах и SHA-256 отдельного согласия. Это **технический барьер**, а не юридическое заключение и не доказательство выполнения закона.

В этом прототипе регистрация предназначена только для пользователей 18+. Подтверждение возраста — заявление пользователя, а не документальная проверка. Если сервис будет доступен несовершеннолетним, запускать эту форму без отдельной правовой и продуктовой доработки нельзя.

## Архитектура и размещение

GitVerse Pages — только статический хостинг и не запускает Spring Boot. Для облачных аккаунтов нужен российский сервер, где в одном origin обслуживаются `public/` и `/api` через Caddy. Репозиторий GitVerse можно оставить для исходного кода; не сохраняй в нём `.env`, выгрузки пользователей, резервные копии или реальные секреты.

Проект предполагает первоначальное размещение всех компонентов, которые могут хранить или получать пользовательские данные, в РФ: web/API, PostgreSQL, backups, runner, журналы/мониторинг и support tools. Физический регион подтверждай договором провайдера — одним регионом в панели облака недостаточно, если snapshots, логи или disaster-recovery реплики размещаются отдельно.

## Технические требования

- Docker Engine + Docker Compose plugin.
- Домен, DNS A/AAAA-запись на сервер.
- Входящие TCP 80 и 443 для автоматического HTTPS через Caddy.
- Java 21 для локального сервера-просмотрщика; backend собирается внутри Docker на Java 21.

## Локальный просмотр интерфейса (без API)

```powershell
.\start.bat
```

Локальный просмотрщик раздаёт только статику из `public/`. Он не запускает Spring Boot и не включает облачные аккаунты.

## Развёртывание на российском VPS

Смотри [DEPLOY_RU.md](DEPLOY_RU.md). До фактического запуска понадобится собственный домен, VPS и сведения об операторе. Не отправляй мне `.env`, пароль БД, recovery keys, SSH private keys или реальные токены.

## Проверки перед сборкой

Из корня проекта:

```bash
node --check app.js
node --check v32.js
node --check account.js
cd backend && mvn test
```

В этой среде выполнена проверка синтаксиса JavaScript и структуры файлов. Maven и Docker в среде сборки не установлены, поэтому Spring Boot backend не был здесь собран или запущен. Перед production обязательно выполни `mvn test` и `docker compose up --build` на своей сборочной машине; устрани все ошибки сборки и проведи тесты безопасности.

## Ограничения текущей версии

- Облачная синхронизация работает только после развёртывания backend на том же origin, что и сайт. На GitVerse Pages она не заработает.
- Recovery code показывается один раз при регистрации/сбросе пароля. Email и SMS восстановления пока не реализованы; если пользователь потеряет ключ, восстановление аккаунта может быть невозможно.
- HTTP-сессии хранятся в памяти одного backend-процесса; рестарт сервера завершает сессии. Для горизонтального масштабирования потребуется Spring Session JDBC/Redis.
- Ограничитель попыток работает в памяти одного процесса; для публичного масштаба дополнительно нужен rate-limit на reverse proxy/WAF и мониторинг.
- Java Runner выключен. Не подключай публичный сторонний Judge0. Нужен отдельный изолированный исполнитель в РФ, с лимитами CPU/RAM/processes, без сети и без доступа к основной БД.
- Документы в `public/privacy.html`, `public/consent.html`, `public/terms.html` — шаблоны, а не готовые юридические формы.
